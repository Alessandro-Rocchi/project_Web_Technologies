1. Introduction and Project Vision

Les Rues du CSS (Cinéma Sur la Seine) is an interactive, multidisciplinary web platform dedicated to cinematic cartography and the cultural exploration of the French Nouvelle Vague (New Wave) in Paris between the late 1950s and late 1960s.

Conceived as part of the Information Modeling and Web Technologies curriculum within the Digital Humanities and Digital Knowledge (DHDK) Master's Degree at the University of Bologna (taught by Prof. Fabio Vitali), the project addresses four interconnected digital humanities and engineering challenges:

1. Historical & Cinematic Research

Identifying authentic Parisian urban locations transformed into open-air film sets by foundational auteurs (Jean-Luc Godard, François Truffaut, Agnès Varda, Jacques Rivette, Chris Marker).

2. Geospatial & Semantic Modeling

Structuring Points of Interest (POIs) using standard GeoJSON and JSON formats, enriched with relational film metadata, multi-tier descriptions (Progressive Disclosure), and vintage vs. modern comparison photography.

3. Spatiotemporal Exploration

Interactive cartography powered by Leaflet.js, automated itinerary calculation via Leaflet Routing Machine, and step-by-step narrative tours with synchronized camera animations.

4. The Full Power of CSS

Delivering 6 completely distinct visual themes switchable at runtime without changing a single character of HTML markup, persisted in localStorage to prove complete separation of semantic content and visual presentation.

2. Conceptual Architecture and Repository Structure

The platform is engineered as a zero-build, modular client-side static web application conforming strictly to W3C standards. This guarantees high performance, zero runtime server overhead, long-term archival resilience, and direct continuous deployment via GitHub Pages.

4.1 Spatial Features and Coordinates (data/paris.geojson)

Conforming strictly to the RFC 7946 GeoJSON specification, data/paris.geojson contains a FeatureCollection of 26 georeferenced Parisian cultural landmarks. All spatial coordinates use the standard WGS84 datum in [longitude, latitude] order.

  • geometry: GeoJSON Point object specifying exact geographical coordinates (e.g., [2.3433, 48.8483]).
  • bbox: Four-element bounding box array [minLng, minLat, maxLng, maxLat] allowing the Leaflet engine to calculate instantaneous spatial framing and layer bounding limits.
  • properties.name: Normalized canonical landmark name, serving as the primary relational join key with paris_metadata.json and tour_data.json.
  • properties.label: Comprehensive human-readable location string (monument name, city, country) displayed in popup headers and queried during Leaflet.PinSearch autocompletion.
  • properties.keywords: Array of thematic classification tags (e.g., ["Top 10 locations", "Cinematic Churches"]) evaluated by filteredLoadGeoData() to dynamically isolate markers for specific tours.
  • properties.movies: Array of cinematic film titles associated with the location, rendered in quick-preview map popups and cross-referenced by director filters.
  • properties.poster_url: Relative asset path to a contemporary preview photograph.

4.2 Extended Historical Metadata (data/paris_metadata.json)

data/paris_metadata.json serves as the encyclopedic monograph store for all 26 monuments. Each record unifies historical chronologies, urban anecdotes, filmographic catalogs enriched with Semantic Web identifiers, and an adaptive narrative matrix:

  • location_name: Canonical landmark title matching paris.geojson.properties.name.
  • locationYear: Historical construction, inauguration, or consecration year (e.g., "1642", "1889").
  • curiosity: Curated historical anecdote, unusual trivia, or secret lore associated with the monument (e.g., Cardinal Richelieu's decapitated skull during the Revolution, or the astronomical gnomon at Saint-Sulpice). Displayed prominently in the modal drawer and exploration panels.
  • image_url: Relative file path to a high-resolution contemporary photograph used for comparative visual study.
  • associated_movie: Relational array modeling a 1-to-many relationship between monuments and cinematic appearances.
  • tones: Multi-audience narrative object implementing a structured $3 \times 3$ Adaptive Tone Matrix.

4.2.1 Filmographic Catalog & Linked Open Data (LOD)

To anchor local historical data within the global Semantic Web knowledge graph, each entry in the associated_movie array incorporates persistent Linked Open Data identifiers alongside comprehensive technical film credits:

  • movie_wikidata: Persistent URI pointing directly to the Wikidata entity (e.g., https://www.wikidata.org/wiki/Q25513 for Paris nous appartient). This anchors the local dataset in the open Linked Data cloud, enabling federated SPARQL cross-querying and interoperability with DBpedia and schema.org graphs.
  • director_viaf: Linked Open Data authority URI pointing to the Virtual International Authority File (VIAF) record (e.g., http://viaf.org/viaf/84270544 for Jacques Rivette). This provides standardized authority control, resolving ambiguity across international library catalogs and cultural heritage repositories.
  • film_id: Unique integer identifier for the film appearance record.
  • film_name: Official cinematic release title.
  • director: Full name of the film director.
  • production_year: Cinematic release year, used for client-side chronological timeline filtering.
  • film_scene_description: Curated narrative describing the exact scene filmed at the monument and its dramaturgical context.
  • starring: Comma-separated list of principal cast members.
  • duration: Official film running time (e.g., "140min").
  • genre: Cinematic classification (e.g., "drama").
  • production: Production companies and studio credits (e.g., "Ajym Films, Les Films du Carrosse").
  • cinematographer: Director of photography (chef opérateur) responsible for visual lighting and camera work (e.g., "Charles L. Bitsch").
  • film_poster_url: Relative asset path to an archival scene still or vintage movie poster.

4.2.2 Multi-Audience Adaptive Tone System (tones)

The platform abandons monolithic text descriptions in favor of a dynamic $3 \times 3$ Narrative Matrix (3 target audience registers $\times$ 3 progressive disclosure tiers), enabling the interface to adapt its pedagogical complexity on the fly:

adult (General Public)

Balanced, culturally nuanced narrative designed for general visitors, cultural tourists, and cinephiles. Blends architectural context, historical background, and cinematic lore.

child (Young Learners)

Engaging, imaginative storytelling using simplified syntax, vivid metaphors, relatable visual analogies, and exciting historical anecdotes designed for educational exploration.

professional (Scholarly)

Rigorous, scholarly prose targeting art historians, urbanists, and film scholars. Details structural typologies, architectural attributions, socio-political context, and film-theory critique.

Within each audience register, the text is structured across three Progressive Disclosure Tiers:

  1. simple_description: Concise single-sentence summary designed for compact UI views, catalogue card headers, and quick-scan previews.
  2. medium_description: 2–3 sentence architectural and historical contextualization, ideal for catalogue card bodies and modal summaries.
  3. detailed_description: Comprehensive, multi-paragraph monograph providing in-depth historical analysis and critical film-scene commentary.

4.4 Cross-Dataset Relational Integrity & Runtime Query Flow

Rather than relying on a monolithic database server, the platform achieves full relational cross-querying on the client side using pure JavaScript asynchronous pipelines across four primary operational contexts:

  1. Catalogue Card Grid Pipeline: loadScriptJson() fetches data/paris_metadata.json into memory. The catalogue controller iterates through the 26 entries, applying pagination (9 items per page via getPaginationRange). Each card is rendered using location_name, locationYear, curiosity, and tones.adult.medium_description.
  2. Cartographic Multi-Criteria Filtering: loadGeoData() (fetching data/paris.geojson) and loadMapJson() (fetching data/paris_metadata.json) execute concurrently. In map_scripts.js, features are enriched with director and production year from metadataJson by matching (m.location_name || m.name).toLowerCase() === (f.properties.name || f.properties.location_name).toLowerCase() (with a dedicated fallback matching "louvre"). The filter engine evaluates dual predicates (active director and decade range), and calls map.fitBounds() to zoom smoothly to the matching subset.
  3. Tour Engine Sequential Synchronization: Upon loading tour.html?keyword=..., loadTourTextData() locates the tour object in data/tour_data.json matching tour.keywords === targetKeyword. Concurrently, filteredLoadGeoData() fetches data/paris.geojson and filters features where feature.properties.keywords.includes(targetKeyword). Next, sortFeaturesByTourOrder() applies matchTourLocation() (normalizing diacritics via Unicode NFD and stripping non-alphanumeric characters) to sort spatial GeoJSON features into the exact sequential order of tour_data.json.locations. During navigation, showParagraph(index) updates stop texts and executes smooth camera flight animations via mapTour.flyTo().
  4. Dynamic Detail Modal & LOD Authority Linking: When a user clicks any Leaflet marker or catalogue card, showLocationDetails(locationName) locates the matching monograph in metadataJson. The modal injects the contemporary photo, historical year, and curiosity anecdote. It renders interactive tabs for the 3 audience tones (adult, child, professional) and 3 progressive disclosure tiers. Finally, it builds a film carousel displaying technical film credits, scene stills, and external hyperlinks pointing to Wikidata (movie_wikidata) and VIAF (director_viaf).

  • 3-Tier Progressive Disclosure Text Reader: Cycles through Short → Medium → Long descriptions via #btn-scopri, resolving narrative strings dynamically from locationTexts.tones[selectedTone] while supporting legacy fallbacks.
  • Linked Open Data (LOD) & Film Metadata Modal (showFilmDetails): Dynamically constructs semantic DOM elements featuring clickable external authority links with target="_blank" to Wikidata ([wikidata]) and VIAF ([viaf]), alongside full film credits (cast, duration, genre, cinematographer, and production companies).
  • Cinematic Itinerary Routing (Leaflet Routing Machine): When a director is selected, calculates and renders a sequential polyline route in signature red (#E32636, 4px weight).
  • 3-Tier Progressive Disclosure Text Reader: Cycles through Short → Medium → Long descriptions via #btn-scopri with intuitive button label updates.

6. Design System and Dynamic CSS Theming

6.1 The Wordplay "Les Rues du CSS"

The project title carries a deliberate, playful meaning that breaks down into three key elements:

  • Thematic focus: Les Rues (The Streets) highlights the site's core mission to map real-life, on-street film locations, honoring the Nouvelle Vague's love for outdoor shooting.
  • Cinematic Acronym: Cinéma Sur la Seine (cinema along the Seine river and Parisian boulevards).
  • Technological Acronym: Cascading Style Sheets (the sole engine behind our six interchangeable themes, transforming the site's look while the HTML structure remains untouched).
"The entire website serves as an academic and practical demonstration of total decoupling: one identical, semantic HTML markup rendered into 6 radically different visual universes."

8. Deployment Pipeline and CI/CD

Continuous Integration and Deployment are automated via GitHub Actions in .github/workflows/deploy-pages.yml: 

name: Deploy static content to Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '24'
      - name: Configure GitHub Pages
        uses: actions/configure-pages@v5
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

Pipeline Highlights:

  • Automatic Push Trigger: Triggers on every push to main, updating the live site within seconds.
  • OIDC Token Security: Uses OpenID Connect credentials for secure GitHub Pages publishing.
  • Zero Compilation Overhead: Pure static files deployed directly without build bottlenecks.

9. Local Development and Setup Guide

Due to browser Cross-Origin Resource Sharing (CORS) security policies restricting fetch() requests over the file:/// protocol, the website must be served through a local HTTP server:

Option 1: Python 3 (Recommended)

# Start a local HTTP server on port 8000
python -m http.server 8000

Navigate to: http://localhost:8000

Option 2: Node.js / npx

# Instant static server
npx serve .

Option 3: VS Code (Live Server)

Install the Live Server extension, right-click index.html, and select "Open with Live Server".
